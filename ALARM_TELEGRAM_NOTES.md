# Alarm + Telegram Notes (2026-04-12)

Короткая фиксация новых знаний по тревогам и уведомлениям.

## Что проверили

- OPFileQuery за сегодня возвращает списки быстро (порядка долей секунды).
- По факту за день может быть много записей (в эксперименте было 64 `jpg` и 64 `h264`).
- Медленно работает именно получение фото тревоги, когда берется `h264` и из него извлекается лучший кадр (`DownloadStart + decode`).

## Текущая схема уведомлений

- Используется только polling через `OPFileQuery` раз в `ALARM_POLL_INTERVAL` секунд.
- Callback-логика из приложения удалена, чтобы поведение было предсказуемым и единым.
- Новая тревога определяется как файл, которого еще нет в `known_files`, после чего отправляется в Telegram.

## Что добавлено в логи

- На bootstrap истории: сколько тревог загружено и сколько считается новыми.
- На каждом poll: `loaded`, `new`, и сырой разрез `raw(jpg,h264)` по окну.

Пример строки:

```text
History poll: window=... loaded=... new=... raw(jpg=...,h264=...)
```

## Telegram: без сжатия фото

- Отправка тревог переключена с `sendPhoto` на `sendDocument`.
- Теперь JPEG уходит как файл `alarm.jpg`, Telegram не пережимает качество как у фото-превью.

## Практический вывод

- Для стабильных уведомлений достаточно корректного polling + дедупа по `FileName`.
- Для скорости UI/истории важен быстрый список OPFileQuery.
- Для качества вложения в Telegram лучше всегда отправка документом.
